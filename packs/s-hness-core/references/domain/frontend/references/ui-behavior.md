# UI Behavior

For each workflow define starting state, hierarchy, available actions, validation, progress, success, failure, cancellation, and recovery.

Use semantic controls and preserve keyboard operation, visible focus, logical focus order, accessible names, status announcements, and error association. Do not rely only on color, hover, animation, gesture, or visual position.

Specify normal, empty, loading, stale, partial, error, disabled, selected, destructive-confirmation, and success states only where the workflow can reach them. Responsive behavior should preserve task priority rather than merely shrink layout.
