# Fe Ui

Start from user tasks, content, information hierarchy, design-system conventions, input methods, accessibility needs, and supported screen sizes. Define behavior before styling details.

Follow [UI behavior](../../references/ui-behavior.md).

## Output

Describe layout hierarchy, component responsibilities, normal/empty/loading/error/disabled/success states, forms and validation feedback, keyboard and focus behavior, accessible names and announcements, responsive adaptation, destructive-action confirmation, and recovery.

## Completion

UI design is complete when every user action and meaningful state has an observable response and critical workflows remain operable without relying only on pointer, color, animation, or visual position. Do not implement components unless requested through the core execution workflow.
